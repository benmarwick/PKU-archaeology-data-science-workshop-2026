# CLAUDE.md

Instructions for AI agents working on this project.

## Language

- Use British English spelling (colour, visualisation, standardisation, centre, analyse)
- Use Palaeolithic (not Paleolithic) in prose

## R Style Preferences

### Pipe and lambda syntax

- Always use the native pipe `|>`, never `%>%`
- Always use the lambda syntax `\(x)`, never `function(x)`

### tidyverse packages

- Always prefer tidyverse packages and functions over base R equivalents
- Preferred packages: tidyverse, ggcorrplot, broom, FactoMineR, factoextra, GGally
- Never use `cat()` or `print()` — use bare evaluations or `glimpse()`
- Use `read_csv()` / `write_csv()` (underscore), never `read.csv()` / `write.csv()` (dot)
- Use `glimpse()` instead of `str()` for inspecting data frames
- Use `drop_na()` instead of `na.omit()`
- Use `count()` for quick frequency tables, `distinct()` for unique values
- Use `dplyr::select()` with explicit namespace when there are conflicts (e.g. with FactoMineR)

### ggplot2

- `ggplot()` and `aes()` are never nested — always connected by `+`
- Never use titles or subtitles on plots
- Only colour palettes allowed are `scale_fill_brewer()` / `scale_colour_brewer()` or `scale_fill_viridis_d()` / `scale_colour_viridis_d()` — never hardcode colours
- Use `theme_minimal()` as the default theme
- Use `labs()` for axis labels and legends
- Use `coord_flip()` for horizontal plots
- Use `geom_pointrange()` for forest plots

### Data types

- Convert categorical variables to factor with explicit `levels` when order matters for plots (e.g. `period`, `raw_material`, `platform_prep`)
- Factor ordering must be meaningful (chronological, geological, etc.), never alphabetical unless that happens to be meaningful

### Code structure

- Use `# =============================================================================` for major section dividers
- Use `# --- Section Name ---` for subsection headers
- Use `# WHY:` comments to explain pedagogical reasoning
- Use `# FIX:` comments to explain solutions
- Use `# INTERPRETATION:` comments for teaching notes
- Use `# NOTE:` comments for important observations
- Use `# ARCHAEOLOGICAL BASIS:` or `# ARCHAEOLOGICAL PRECEDENT:` for domain context
- Inline comments after code are OK (e.g. `x <- 1  # this is a note`)
- Never use multi-line docstrings or comment blocks — one short line max

### Statistical packages

- For PCA: use `FactoMineR::PCA()` and `factoextra` for visualisation
- For tidy model output: use `broom::tidy()`
- For chi-square residual plots: use `ggcorrplot()`
- For pairs plots: use `GGally::ggpairs()`

## Project Structure

- Lesson R files live in `code/` with pattern `DD-D_day_lesson.R`
- Slides live in `slides/` as `.pptx` files
- Student data: `lithics_raw.csv` (spoiled), `lithics_clean.csv` (instructor verification)
- Instructor-only script: `code/00_simulate_lithics.R`
- Live demo script: `code/live-demo-script.R` (generated by `code/extract_lesson_code.R`)

## Dataset Context

This workshop uses a simulated Palaeolithic lithic dataset (300 artefacts, 100 per period). Variable distributions follow published literature on raw material provisioning (Bourguignon et al. 2008), platform preparation (Shimelmitz et al. 2014), and blade technology (Bar-Yosef & Kuhn 1999). Every variable is designed to produce clean, interpretable statistical results for teaching purposes.
